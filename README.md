# ربات دانلود از لینک (Video Downloader Bot)

یک ربات تلگرام کوچک: **لینک می‌فرستی، ویدیو/فایل را دانلود می‌کند و همان‌جا در چت تحویل می‌دهد.**

| داخل این پروژه **هست** | داخل این پروژه **نیست** |
|---|---|
| ✅ دانلود لینک مستقیم (aria2c، چند اتصاله) | ❌ هیچ کتابخانه/سرویس اشتراک فایل همتا |
| ✅ دانلود از سایت‌ها با yt-dlp (یوتیوب، اینستاگرام، توییتر/X، تیک‌تاک…) | ❌ دانلودرهای مدیریت‌شدهٔ خارجی |
| ✅ صداگیری mp3 با ffmpeg | ❌ آپلود به فضای ابری |
| ✅ صف، پیشرفت زنده، لغو، پاک‌سازی خودکار | ❌ سشنِ کاربرِ تلگرام (فقط Bot API رسمی) |
| ✅ ارسال به خودِ چت کاربر | ❌ وب‌سرور عمومی و پورتِ ورودی |

فقط با **Bot API رسمی** کار می‌کند (یک ربات معمولی، نه یوزربات) و هیچ پورتِ بازی ندارد؛
پس روی هر پلتفرمی که «سرویس وب» می‌خواهد هم مشکلی ایجاد نمی‌کند.

---

## ۱) راه‌اندازی روی Railway (گام‌به‌گام)

1. در [@BotFather](https://t.me/BotFather) یک ربات بساز: `/newbot` → توکن را کپی کن.
2. آیدی عددی خودت را بگیر: در تلگرام به [@userinfobot](https://t.me/userinfobot) پیام بده.
3. در Railway: **New Project → Deploy from GitHub repo → همین ریپو** را انتخاب کن.
4. تب **Variables** این دو را اضافه کن:
   - `BOT_TOKEN` = توکنِ BotFather
   - `OWNER_ID` = آیدی عددی خودت (تا فقط تو بتوانی استفاده کنی)
5. صبر کن بیلد تمام شود → در **Deploy Logs** این خط را می‌بینی:
   `✅ ربات @your_bot آماده است`
6. در تلگرام به ربات خودت `/start` بده و یک لینک بفرست.

> 💾 اگر می‌خواهی فایل‌ها بین ری‌استارت‌ها بمانند (پیش‌فرض لازم نیست، چون فایل‌ها بعد از ارسال پاک می‌شوند)
> می‌توانی یک **Volume** روی مسیر `/tmp/downloads` وصل کنی.

## ۲) اجرای محلی با Docker

```bash
docker build -t vdl-bot .
docker run --rm -e BOT_TOKEN=... -e OWNER_ID=... vdl-bot
```

## ۳) متغیرهای محیطی

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `BOT_TOKEN` | — | **اجباری.** توکن ربات از BotFather |
| `OWNER_ID` | `0` | آیدی عددی مالک (همیشه دسترسی دارد) |
| `ALLOWED_USERS` | خالی | آیدی‌های مجاز با کاما؛ خالی باشد فقط مالک دسترسی دارد |
| `MAX_UPLOAD_MB` | `49` | سقف ارسال. تلگرام برای ربات‌ها ۵۰MB است؛ بیشتر از ۵۰ نگذار |
| `MAX_DOWNLOAD_MB` | `400` | سقف فایل ورودی (بیشتر شد، دانلود قطع می‌شود) |
| `MAX_CONCURRENT` | `2` | چند دانلود هم‌زمان برای کل ربات |
| `AUTO_FALLBACK` | `1` | اگر فایل از سقف ارسال بزرگ‌تر شد، خودکار نسخهٔ ۴۸۰p را بگیرد |
| `DOWNLOADER` | `auto` | `auto` / `ytdlp` / `aria2` — اجبار به یک موتور دانلود |
| `COOKIES_FILE` | خالی | مسیر فایل کوکی (برای سایت‌هایی که ورود/سن می‌خواهند) |
| `DOWNLOAD_DIR` | `/tmp/downloads` | پوشهٔ موقت |
| `DISK_LIMIT_MB` | `2000` | اگر پوشهٔ موقت از این بگذرد، پاک‌سازی می‌شود |
| `KEEP_FILES` | `0` | `1` = فایل‌ها بعد از ارسال پاک نشوند |

## ۴) دستورهای ربات

| دستور | کار |
|---|---|
| لینک را بفرست | دانلود تا ۷۲۰p و ارسال |
| `/low لینک` | نسخهٔ کم‌حجم (تا ۴۸۰p) |
| `/audio لینک` | فقط صدا (mp3) |
| `/status` | وضعیت دانلودها و دیسک |
| `/cancel` | لغو دانلود خودت |
| `/id` | آیدی عددی تو (برای `ALLOWED_USERS`) |
| `/help` | راهنما |

## ۵) محدودیت‌ها (مهم)

- **سقف ۵۰ مگابایت:** این سقفِ خودِ تلگرام برای ربات‌هاست. فایل بزرگ‌تر از آن با
  Bot API قابل ارسال نیست. راه‌حل‌های ربات: `AUTO_FALLBACK` (۴۸۰p)، `/audio`، یا `/low`.
- اگر فایل بزرگ‌تر از `MAX_UPLOAD_MB` باشد و بالاخره هم جا نشود، ربات همان را در پیام توضیح می‌دهد.
- سایت‌های خصوصی/سن‌دار به `COOKIES_FILE` نیاز دارند.
- yt-dlp با هر ری‌دیپلوی، آخرین نسخه نصب می‌شود (پین سخت نشده) تا سایت‌های جدید کار کنند.

## ۶) توسعه

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
BOT_TOKEN=... OWNER_ID=... python bot.py
```
