# ربات دانلود از لینک (Video Downloader Bot) — نسخهٔ ۲.۵

یا لینک را می‌فرستی، یا دستور **`/leech لینک`** را می‌زنی (مثل ربات‌های لیچ) →
**کیفیت‌های موجود با حجم** نشان داده می‌شود → انتخاب می‌کنی → دانلود با
**نوار پیشرفت مربعی سبز** انجام می‌شود → فایل با **کپشن (عنوان + توضیح + لینک اصلی)**
و **به‌شکل ویدیو** تحویل داده می‌شود.

| داخل پروژه **هست** | داخل پروژه **نیست** |
|---|---|
| ✅ لینک مستقیم (aria2c، ۸ اتصال) و سایت‌ها (yt-dlp) | ❌ سشنِ کاربر تلگرام (فقط Bot API رسمی) |
| ✅ هر فرمت: `mp4`، `mkv`، `webm`، **`ts`**، `m3u8`/HLS، `mp3` و… | ❌ وب‌سرور عمومی / پورت ورودی |
| ✅ تبدیل خودکار غیر-mp4 به mp4 **بدون افت کیفیت** (`-c copy`) | ❌ کتابخانهٔ اشتراک فایل همتا |
| ✅ منوی کیفیت با تخمین حجم + دکمه | ❌ یوزنت/NZB |
| ✅ نوار پیشرفت مربعی برای **دانلود و آپلود** | ❌ دانلودر مدیریت‌شدهٔ خارجی |
| ✅ دستور **`/leech لینک`** (و ریپلای روی پیامِ دارای لینک) | ❌ آپلود به فضای ابری |
| ✅ سقف حجم تا **۲GB** (با سرور Bot API محلی) | ❌ سشنِ کاربر / حساب شخصی |

---

## ۱) نصب روی Railway — حالت ساده (سقف ۵۰MB)

1. در [@BotFather](https://t.me/BotFather) → `/newbot` → توکن را بگیر.
2. آیدی عددی خودت را از [@userinfobot](https://t.me/userinfobot) بگیر.
3. Railway → **New Project → Deploy from GitHub repo →** `baddarksss/video-downloader-bot`
4. تب **Variables**:
   - `BOT_TOKEN` = توکن ربات
   - `OWNER_ID` = آیدی عددی خودت
5. Deploy → در لاگ: `✅ ربات @your_bot آماده است` → در تلگرام `/start`.

> در این حالت سقف ارسال ۵۰MB است (سقف خود تلگرام برای ربات‌ها).

## ۲) تا ۲ گیگابایت (نصبِ سرور Bot API محلی — داخل همین سرویس)

سقف ۵۰ مگابایت، محدودیتِ خودِ `api.telegram.org` است. برای ۲۰۰۰MB باید یک
**سرور Bot API محلی** بالا بیاید. در این نسخه، آن سرور **داخل همان کانتینر ربات**
اجرا می‌شود؛ پس فقط یک سرویس داری و همان متغیرها کافی است.

**فقط این متغیرها را روی سرویس ربات بگذار (Railway → Variables):**

| متغیر | مقدار | اجباری؟ |
|---|---|---|
| `BOT_TOKEN` | توکن ربات از BotFather | ✅ |
| `OWNER_ID` | آیدی عددی خودت | ✅ |
| `TELEGRAM_API_ID` | api_id از my.telegram.org | ✅ برای ۲GB |
| `TELEGRAM_API_HASH` | api_hash از my.telegram.org | ✅ برای ۲GB |
| `TELEGRAM_LOCAL` | `1` | ✅ برای ۲GB |
| `TELEGRAM_HTTP_PORT` | `8081` | اختیاری (پیش‌فرض همین) |
| `TELEGRAM_WORK_DIR` | `/data` | اختیاری (پیش‌فرض همین) |
| `TELEGRAM_TEMP_DIR` | `/data/tmp` | اختیاری (پیش‌فرض همین) |

سپس **Redeploy**. در لاگ باید ببینی:

```
[entry] 🚀 اجرای سرور Bot API محلی روی پورت 8081 (پوشه: /data)
[entry] ✅ سرور Bot API محلی آماده است → سقف ارسال ۲۰۰۰MB
✅ ربات @your_bot آماده است  (نسخه 2.5)
   سرور API: http://127.0.0.1:8081 → سقف ارسال 2000MB ≈ 1.95GB
```

- `BOT_API_BASE` را **ست نکن** (خودش لوکال را انتخاب می‌کند). اگر دستی ست کنی،
  سرور محلی اجرا نمی‌شود و همان آدرسِ تو استفاده می‌شود.
- اگر `TELEGRAM_API_ID/HASH` نباشد یا سرور محلی بالا نیاید، ربات خودکار روی
  API ابری (۵۰MB) ادامه می‌دهد — هیچ‌وقت بدون سرویس نمی‌مانی.
- در `/status` می‌توانی ببینی: «سرور API: محلی»، «سقف ارسال: 2000MB ≈ 1.95GB»
  و **«فضای آزاد دیسک: X از Y»** (تا بدانی جا برای فایل بزرگ هست یا نه).

### 💾 توصیه برای فایل‌های چند گیگی: یک Volume روی `/data`
مسیر دانلود و فایل‌های موقتِ سرور محلی هر دو داخل `/data` هستند. با وصل‌کردن یک
Volume روی `/data` (Railway → سرویس → Volumes، مثلاً ۱۰GB) هم جا مطمئن می‌شود و هم
فایل‌های موقت بین ری‌استارت‌ها می‌مانند. فضای آزاد را خود ربات در `/status` و در
لاگِ راه‌اندازی نشان می‌دهد.

> مصرف دیسک در بدترین حالت ≈ ۲ برابر حجم فایل است (فایل دانلودشده + نسخهٔ در حال
> ارسال). برای یک ویدیوی ۲ گیگی، حدود ۴–۵ گیگابایت فضای آزاد بگذار.
> رم سرور محلی هم در تست ما ~۳۷MB بود؛ نگرانی‌ای نیست.

## ۳) اجرای محلی

```bash
docker build -t vdl-bot .
docker run --rm -e BOT_TOKEN=... -e OWNER_ID=... vdl-bot
# یا بدون داکر:
pip install -r requirements.txt
BOT_TOKEN=... OWNER_ID=... python bot.py
```

## ۴) متغیرهای محیطی

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `BOT_TOKEN` | — | **اجباری** |
| `OWNER_ID` | `0` | آیدی عددی مالک |
| `ALLOWED_USERS` | خالی | آیدی‌های مجاز با کاما |
| `BOT_API_BASE` | `https://api.telegram.org` | آدرس سرور Bot API (برای ۲GB → سرور محلی) |
| `MAX_UPLOAD_MB` | خودکار | ۵۰ برای ابری، ۲۰۰۰ برای سرور محلی |
| `MAX_DOWNLOAD_MB` | `max(2200, سقف+۴۰۰)` | سقف فایل ورودی |
| `MAX_CONCURRENT` | `2` | دانلود هم‌زمان |
| `FORCE_MP4` | `1` | غیر-mp4 را با کپی به mp4 تبدیل کند تا ویدیو بماند |
| `REENCODE` | `0` | `1` = تبدیل کدک (کند؛ وقتی کدک با mp4 سازگار نیست) |
| `DOWNLOADER` | `auto` | `auto` / `ytdlp` / `aria2` |
| `COOKIES_FILE` | خالی | کوکی برای سایت‌های نیازمند ورود |
| `MAX_OPTIONS` | `6` | حداکثر تعداد کیفیت در منو |
| `MENU_TTL_S` | `900` | اعتبار منوی کیفیت |
| `DOWNLOAD_DIR` | `/tmp/downloads` | پوشهٔ موقت |
| `DISK_LIMIT_MB` | `6000` | پاک‌سازی خودکار وقتی پوشه از این بگذرد |
| `KEEP_FILES` | `0` | فایل‌ها بعد از ارسال پاک نشوند |
| `MAX_LOG_LINES` | `400` | سقف خطوط هر لاگ |
| `LOG_KEEP_ON_SUCCESS` | `0` | `1` = لاگِ دانلود موفق هم نگه داشته شود |
| `DISK_SELFTEST_MB` | `0` | مثلاً `2400` = هر بار راه‌اندازی، واقعاً ۲۴۰۰MB می‌نویسد و در لاگ می‌گوید جا هست یا نه (فایل آزمایشی پاک می‌شود) |

## ۵) دستورها

| کار | توضیح |
|---|---|
| **`/leech لینک`** | **دستور لیچ**: لینک را می‌دهی، کیفیت‌ها با حجم می‌آید، انتخاب می‌کنی، دانلود و ارسال |
| `/leech` (ریپلای) | روی پیامی که لینک دارد ریپلای کن و `/leech` بزن |

| `/help` | راهنما |

## ۶) جزئیات رفتار

### 🔗 دستور لیچ (`/leech`)

همان کارِ ربات‌های لیچ، ولی با موتورِ این ربات (yt-dlp + aria2c + ffmpeg):

- `/leech https://site.com/film` → کیفیت‌ها با حجم می‌آید → انتخاب → دانلود → ارسال
- **دو مرحله‌ای**: اول `/leech` را بزن، بعد لینک را بفرست — همان کار را می‌کند
- `/leech` روی **ریپلای** پیامی که لینک دارد هم کار می‌کند
- لینک چندتایی در یک پیام: اولین لینک پردازش می‌شود
- نتیجه همیشه **ویدیوی قابل‌پخش** است (اگر لازم باشد بدون افت کیفیت به mp4 تبدیل می‌شود)،
  و کپشنش **لینک اصلی** را دارد

- **منوی کیفیت:** با `yt-dlp -J` ارتفاع‌های موجود + تخمین حجم (ویدیو + صدا) محاسبه و
  حداکثر `MAX_OPTIONS` گزینه به‌ترتیب نزولی نشان داده می‌شود؛ گزینهٔ «فقط صدا (mp3)» هم هست.
  برای لینک مستقیم (فایلی که yt-dlp نمی‌شناسد) یک گزینه با حجم واقعی (`Content-Length`) می‌آید.
- **هر فرمت:** `.ts`/`.mkv`/`.webm`/`.mov`/`m3u8` دانلود می‌شود. اگر mp4 نبود، با
  `ffmpeg -c copy -movflags +faststart` (بدون افت کیفیت) به mp4 تبدیل می‌شود و
  **به‌شکل ویدیو** فرستاده می‌شود. اگر کدک ذاتاً با mp4 سازگار نباشد (مثل vp8/vorbis)،
  به‌شکل فایل می‌رود و در کپشن همین توضیح داده می‌شود (با `REENCODE=1` می‌شود تبدیل کدک کرد).
- **نوار پیشرفت:** `⬇️ دانلود 🟩🟩🟩⬜️… 42%` با حجم/سرعت/زمان باقی‌مانده، سپس مرحلهٔ
  تبدیل، سپس `⬆️ آپلود 🟩…`. برای فایل‌های بزرگ، آپلود **جریانی** است (رم پر نمی‌شود).
- **کپشن:** عنوان + (⏱ مدت · 🎬 کیفیت · 💾 حجم) + توضیح + **لینک اصلی** به‌صورت لینک
  قابل‌کلیک (`parse_mode=HTML`) و فیلم به‌شکل ویدیوی قابل‌پخش (`supports_streaming`).
- **لاگ و عیب‌یابی (v2.1):**
  - هر دانلود یک لاگِ کامل دارد: دستورهای اجراشده (yt-dlp/aria2c/ffmpeg)،
    خروجی پروسه‌ها، کد خروج، حجم‌ها، زمان‌ها و مرحلهٔ خطا.
  - اگر فایل نیامد، پیام خطا **دکمهٔ «📄 لاگ»** نشان می‌دهد؛ با `/log` هم می‌شود
    همان لاگ را گرفت (کوتاه ⇒ متن، بلند ⇒ فایل `log-*.txt`).
  - **بعد از هر دانلودِ موفق، لاگ پاک می‌شود**؛ با شروع دانلود بعدی هم لاگِ قبلی
    پاک می‌شود. پس لاگ فقط برای «لینکی که فایل نداد» نگه داشته می‌شود.
  - در `/status` هم می‌بینی لاگ ذخیره شده یا خالی است.

## ۷) محدودیت‌ها

- بدون سرور محلی، تلگرام اجازهٔ ارسال بیش از ۵۰MB به ربات‌ها نمی‌دهد (پیام واضح داده می‌شود).
- دانلود تا ۲GB روی Railway به حافظهٔ دیسک کانتینر نیاز دارد؛ ربات بعد از ارسال پاک می‌کند
  و اگر لازم شد یک Volume روی `DOWNLOAD_DIR` وصل کن.
- سایت‌های خصوصی/سن‌دار به `COOKIES_FILE` نیاز دارند.
